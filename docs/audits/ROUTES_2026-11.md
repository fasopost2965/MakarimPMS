# Audit des routes du prototype — novembre 2026

**Date :** 2026-11-06 · **Périmètre :** `prototype/` (aucune modification de `backend/` ni `frontend/`)
**Origine :** demande « vérifier toutes les routes existantes et manquantes ».

## 1. Méthode

L'audit est **exécuté**, pas déclaré : un script compare les quatre sources de vérité du
routage du prototype.

| Source | Fichier | Ce qui y est déclaré |
|---|---|---|
| Routes rendues | `src/App.jsx` (`PAGES`) | clé → titre, sous-titre, composant |
| Entrées de menu | `src/components/Shell.jsx` (`NAV`) | clé, libellé, icône, option de module |
| Permissions | `src/data.js` (`PERMISSIONS`) | clé, libellé, groupe (matrice RBAC) |
| Droits par rôle | `src/data.js` (`PROFILS.*.ecrans`) | écrans ouverts à la connexion |

Résultat de l'exécution :

```
PAGES 13 : dashboard, chambres, reservations, restaurant, conference, caisse,
           police, tournees, documents, roles, stock, channel, tarifs
NAV   13 : (même ensemble)
sans entrée de menu    : []
menu sans écran        : []
sans permission        : []
permission sans écran  : []
```

Aucune route orpheline, aucun menu mort, aucune permission fantôme.

## 3. Ce qui manquait, et qui a été corrigé

1. **Aucune route n'existait dans l'URL.** L'écran courant n'était qu'un `useState` : un
   rafraîchissement ramenait au tableau de bord, un lien ne pouvait pas désigner un écran, et
   le bouton « précédent » du navigateur ne faisait rien.
   → Chaque écran a désormais une route (`#/stock`), l'URL est mise à jour à la navigation, un
   lien direct est honoré après connexion, et une clé inconnue retombe sur `#/dashboard`.
2. **Pas de garde d'accès sur les routes directes.** Un lien `#/roles` ouvert par un compte
   réception était arrêté par l'effet de garde RBAC (retour à l'écran d'accueil du rôle) — le
   comportement était correct mais implicite. Il est documenté ici et couvert par le test.
3. **Pas de page de connexion dans le périmètre routé.** L'application est désormais
   entièrement derrière le portail : sans session, aucune route ne rend un écran (retour
   anticipé placé après tous les hooks — cf. correctif du 2026-11-06).
4. **Écrans absents, créés depuis :** `stock`, `channel`, `tarifs` (réecrit), `login`.

## 4. Routes volontairement absentes

| Suffixe | Pourquoi |
|---|---|
| `/login` | le portail est un état, pas un écran interne : une session absente suffit |
| `/parametres` | fusionné dans `/tarifs` (grille, fiscalité, identité, modules) |
| `/rapports` | les rapports sont des **documents** imprimables (`/documents`) et des exports CSV/Excel dans chaque écran, pas un écran séparé |
| `/chambre/:numero` | le plan des chambres ouvre un panneau latéral ; une URL par chambre n'apporte rien à 30 chambres |
| `/client/:id` | pas d'identifiant client stable dans le jeu de démonstration ; le dossier client s'ouvre depuis une réservation |

## 5. Contrôles automatisés

Le test de fumée (jsdom) parcourt les 13 routes, ouvre un lien profond (`#/stock`), vérifie le
retour au portail à la déconnexion et l'absence d'erreur console. Il est rejoué avant chaque
commit touchant l'ossature.

## 6. Suites

- Passer d'un routage par `hash` à un vrai routeur (historique, `pushState`, transitions) le
  jour où le prototype devient l'application réelle : le contrat de clés ne change pas.
- Protéger chaque écran par une requête serveur : la garde client est un confort, la garde
  serveur est la règle (**BR-TR-004**).
- Ajouter une route `#/404` explicite quand le nombre d'écrans dépassera la vingtaine.
